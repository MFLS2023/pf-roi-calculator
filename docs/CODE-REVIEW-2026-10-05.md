## 二、P1 严重问题

### P1-1 桌面端「多方案对比」表格被强制横向滚动，核心功能失效

**现象**：在 1440px 桌面下，对比表容器仅 **398px**，而表格 `min-width: 520px`，
**122px 内容被裁掉**，底部出现横向滚动条。「总投入」列表头被截断为「总投…」，
最右侧的「载入 / 删除」操作列**完全不可见**。

实测数据（1440px 视口，已保存 2 个方案）：

```
hostW (#compare-host)     400px
scrollClientW             398px
scrollW / tableW          520px
FORCED_H_SCROLL           true
hiddenPx                  122px
```

**根因**（`src/styles/base.css:212-247`）：

```css
@media (min-width: 1024px) {
  .app__body { grid-template-columns: minmax(0, 400px) minmax(0, 1fr); }

  .pane--form    { grid-column: 1; grid-row: 1; }
  #compare-host  { grid-column: 1; grid-row: 2; }   /* ← 只有 400px */
  .pane--results { grid-column: 2; grid-row: 1 / span 2; }
}
```

作者**有意**把对比区放在左列下方（注释说明是为了给 sticky 结果面板留出滚动距离），
但这个决定与「对比表需要 520px」直接冲突。桌面端恰恰是横向对比最该发挥作用的场景，
现在却必须在小框里左右拖拽才能看全，**等于把该功能在桌面端废掉了**。

**证据**：`docs/review/compare-table-clipped.png`

**改进建议**（三选一，推荐 A）：

- **A（推荐）** 让对比区跨满整行：`#compare-host { grid-column: 1 / -1; grid-row: 3; }`，
  并把 `.pane--results { grid-row: 1 / span 2; }` 保持跨前两行。既保住 sticky，又给表格 933px 宽度。
- **B** 保持左列布局，但把 `.compare__table { min-width: 520px }` 降到 ≤380px，
  同时精简列（合并「期望买号」到 ROI 单元格副标题）。
- **C** 桌面端把对比表改成「卡片流」而非表格。

### P1-2 浅色主题主按钮文字对比度仅 3.70:1，不达 WCAG AA

**现象**：浅色主题下主按钮使用 `linear-gradient(135deg, #b4790b, #94590a)` + 白字。
按 WCAG 2.1，15px/600 字重**不属于「大号文本」**，要求 4.5:1。

实测对比度：

| 组合 | 对比度 | AA (4.5) |
| :--- | ---: | :--- |
| 白字 on `#b4790b`（渐变亮端） | **3.70** | ❌ 失败 |
| 白字 on `#94590a`（渐变暗端） | 5.69 | ✅ |

暗色主题无此问题（深墨字 on 琥珀底 = 9.89:1，非常出色）。

**改进建议**：
- 把浅色主题按钮渐变整体压深一档，例如 `#8a5a06 → #6f4705`（预计 ≈6.5:1）；
- 或把按钮文字改为 16px/700 使其落入「大号文本」阈值（仅需 3:1）——但这会破坏与暗色主题的字号一致性；
- **推荐**压深渐变，视觉冲击力几乎不变。

---

### P1-3 `--text-faint` 在两种主题下均不达 AA，波及 20 处小字

**现象**：`--text-faint` 被 **20 个**文本节点使用（实测统计），包括：

- 预设免责声明整段（11px，`#989da6` on `#faf8f3`）
- 全部 9 个 `field__unit`（`(USD)` / `(天)`，12px）
- 3 个分组标签（`一次性投入` / `概率计算` / `收益结算`，11px）
- 品牌副标题、页脚、对比区提示、ROI 说明行

实测对比度：

| 主题 | 前景 | 背景 | 对比度 | AA (4.5) |
| :--- | :--- | :--- | ---: | :--- |
| 浅色 | `#989da6` | `#faf8f3` | **2.57** | ❌ |
| 浅色 | `#989da6` | `#ffffff` | **2.56** | ❌ |
| 暗色 | `#5f6975` | `#171d26` | **3.04** | ❌ |
| 暗色 | `#5f6975` | `#151a22` | 3.07 | ❌ |

**2.57:1 属于严重不足**——不是「稍微淡一点」，而是「在普通显示器/户外/中年视力下基本读不清」。
而其中「(USD)」「(天)」是**功能性单位标识**，读不清会直接影响填表正确性。

**改进建议**：
- 浅色：`--text-faint` 从 `#989da6` 调到 **`#6b717c`**（即当前 `--text-muted` 的值，≈4.9:1），
  并把 `--text-muted` 顺带下调到 `#5a6069`；
- 暗色：从 `#5f6975` 调到 **`#8d97a5`**（≈5.9:1）；
- 若想保留「弱化」的视觉层级，改用**字号/字重**而非降低对比度来区分层级。

## 三、P2 中等问题

### P2-1 极端输入产生科学计数法字符串并撑破卡片

**现象**：输入可键入的极端值后，指标卡片渲染出 `$9.998999999999984e+93`。

实测（320px 视口，`回撤=1 / 目标=99999 / 天数=9`）：

```
期望购买账号    9.999999999999985e+89     scrollWidth 168 vs 可用 94  → 被裁
预计获资账号    9.999999999999993e+44     同上
买号成本        $9.998999999999984e+93    同上
激活费用        $9.998999999999993e+48    同上
总投入成本      $9.998999999999984e+93    同上
```

**根因**：`Number.prototype.toFixed()` 在数值 ≥ 1e21 时**返回指数形式**，
所以 `formatCount` / `formatMoney` 的 `.toFixed(2)` 并不能兜住溢出。
且 `.metric__value` 只有 `white-space: nowrap`，**没有** `overflow`/`text-overflow`，
长值被硬裁（无省略号），用户看到的是半个乱码。

**改进建议**：
1. `formatter` 增加数量级上限：`|v| >= 1e6` 时改用 `1.2M` / `3.4B` 等紧凑记法；
2. 输入侧加软上限（如 `max="1000000"`）或超限时给出提示；
3. `.metric__value` 补 `overflow: hidden; text-overflow: ellipsis;` 作为兜底。

### P2-2 设计令牌语义倒置：`--positive` / `--negative` 被复用为状态色

**现象**（`src/styles/components.css:753-759`）：

```css
.toast--success { border-left-color: var(--negative); }  /* 语义上是「亏损色」 */
.toast--error   { border-left-color: var(--positive); }  /* 语义上是「盈利色」 */
```

由于本项目采用红涨绿跌，`--positive` = 红、`--negative` = 绿，
所以「成功=绿、错误=红」在**当前配色下恰好看起来正确**，但原因是错的——
它借用的是 P&L 语义，不是状态语义。

**风险**：一旦有人把配色切回欧美惯例（涨绿跌红），成功提示会变成红色、错误提示变绿色，
**变成真正的 bug 且很难排查**。

**改进建议**：拆出独立的状态令牌 `--success` / `--danger`，
`--positive` / `--negative` 只用于盈亏数值。

---

### P2-3 移动端触控目标偏小（28–40px，低于 44px 推荐值）

实测（390px 视口）低于 44px 的可点击元素：

| 控件 | 高度 | 出现位置 |
| :--- | ---: | :--- |
| `.btn--icon`（删除方案，**破坏性操作**） | **28px** | 对比表每行 |
| `.btn--chip`（载入 / 清空全部 / 重置变量 / 安装） | **28px** | 多处 |
| `.btn--secondary`（导出分享图 / 保存当前方案） | 38px | 结果区、对比区 |
| `.select`（预设 / 语言） | 38px | 工具栏 |
| `.compare__name`（方案命名输入框） | 38px | 对比区 |

注：`.field__input` 已有 `@media (pointer: coarse) { height: 44px }` 保护（✅ 做得好），
但**按钮类没有同等保护**。

WCAG 2.2 SC 2.5.8 最低要求 24×24（当前勉强达标），
但 Apple HIG / Material 均推荐 44×44。删除按钮 28px 尤其危险——误触会丢数据。

**改进建议**：在 `@media (pointer: coarse)` 内统一提升交互控件到 44px 最小高度，
或至少给 `.btn--icon` 加透明扩大的命中区域（`padding` + `margin: -Npx`）。

### P2-4 预设免责声明是「一大段 11px 低对比灰字」

**现象**：预设切换后，说明区会塞进 **300+ 字符**的中文段落（含 ⚠️ 提示、置信度徽章、
社区维护免责声明），全部是 11px + `--text-faint`（2.57:1）。
在 1440px 桌面下它横跨整行，形成一堵灰字墙；在移动端更糟。

同时，页面存在**三处免责类文本**：预设说明、页脚免责声明、ROI 卡内「红涨绿跌」图例——
信息冗余，用户会全部略过。

**改进建议**：
- 默认只显示「机构名 + 核实月份 + 置信度徽章 + 一句话摘要」，
  完整说明折叠到「详情」展开；
- 三处免责合并为一处；
- 至少把字号提到 12px、颜色提到 AA 达标值。

### P2-5 桌面端右列留白 111px，视觉重心失衡

实测（1440px）：左列高 541px（底边 794），右列高 430px（底边 683），**下方空出 111px**。

这是 `sticky` 设计意图带来的副作用（注释里写明了要给 sticky 留滚动距离），
但视觉上右列明显「短一截」，卡片右下角形成一块空白，观感不够完整。

**改进建议**：若采纳 P1-1 的方案 A（对比区跨满整行），
右列会获得更多纵向内容（例如把「导出分享图」按钮下移、或补充「保本出金」等小指标），
顺带缓解这一失衡。

### P2-6 「最优」行高亮被 hover 样式覆盖

```css
.compare__table tbody tr:hover td:first-child { background: var(--surface-subtle); }
.compare__row--best td:first-child { background: var(--positive-soft); }
```

前者特异性 (0,3,3) 高于后者 (0,2,1)，**鼠标悬停「最优」行时绿色高亮会消失**，
产生闪烁感，削弱「最优」这一关键视觉标记。

**改进建议**：把 best 规则改为 `.compare__table tbody tr.compare__row--best td`，
或给 hover 规则加 `:not(.compare__row--best)`。

**建议**：新增 `presetVerified: '核实于 {month}' / 'verified {month}'` 键。

### P3-2 与原始规格书的整体偏离（需确认是否有意）

重写把设计语言从「冷灰蓝 + 白卡 + 靛紫渐变」整体换成了「暗色优先终端账本 + 琥珀色」，
并**反转了盈亏配色语义**。与规格书 `pf_roi_calculator_spec.md` 的差异：

| 项目 | 规格书 | 当前实现 |
| :--- | :--- | :--- |
| 页面背景 | `linear-gradient(135deg,#eef2f6,#e0e7ff)` | 暗色 `#0c0f14→#11151c` / 浅色暖纸 `#f3f1ea→#eae7de` |
| 主容器圆角 | `24px` | `16px` |
| 主色 | 靛紫渐变 `#3b82f6→#8b5cf6` | 琥珀 `#f0a63c` |
| 盈亏语义 | 负红 / 正绿 | **负绿 / 正红**（红涨绿跌） |
| 指标网格 | 3 列 | 手机 2 列 / ≥640px 4 列 |
| 默认主题 | 浅色 | **暗色优先** |

这些改动**本身质量不错**（红涨绿跌对国内用户确实更直觉，4 列网格消除了原来的空占位格，
暗色主题执行得很完整），但它是**对已批准规格书的实质性变更**。

**建议**：明确「规格书是否仍是验收基线」。若是，需回退；若已口头同意改版，
建议把新设计语言写进 `docs/DESIGN.md` 并同步更新规格书，避免后续贡献者按旧文档改回去。

### P3-4 次要排版瑕疵

- `.metric__value--sm`（16px）与 `.metric__value` 基础值差异已统一为 16px，
  但 CSS 中仍保留 `--sm` 修饰类，属于冗余；
- `.roi__value` 使用 `font-size: 38px`，而移动端 `@media (max-width: 380px)` 降到 33px——

  建议把过渡改为 `transition: none` 或缩短到 120ms 以内。

## 附：审查方法与可复现性

所有结论均可通过以下方式复现：

```bash
npm run build
npm run preview          # :4173
```

然后用浏览器 DevTools 在 1440 / 1024 / 390 / 320 四个宽度下执行：

```js
// 对比表是否被强制横向滚动
const s = document.querySelector('.compare__scroll');
s.scrollWidth > s.clientWidth + 1;

// 网格列定义
getComputedStyle(document.querySelector('.app__body')).gridTemplateColumns;
getComputedStyle(document.querySelector('.metrics')).gridTemplateColumns;

// 主题令牌
getComputedStyle(document.documentElement).getPropertyValue('--text-faint');
```

对比度按 WCAG 2.x 相对亮度公式计算：

```
L = 0.2126·R + 0.7152·G + 0.0722·B   （R/G/B 为线性化后的 sRGB 分量）
contrast = (L_light + 0.05) / (L_dark + 0.05)
```

截图证据见 `docs/review/`。
